# RERA-06 queue report prototype

Run `node scripts/render-queue-report.mjs tests/fixtures/rera-06-queue.json 2026-01-02T12:00:00Z` from the repository root. The optional final argument fixes the report time for reproducible checks; otherwise the current clock is used. Run `node --test tests/*.test.mjs` for validation.

Input is a **local JSON snapshot** with `issues` and `pullRequests` arrays. Each issue needs `number`, `title`, `url`, `state` (`open` or `closed`, case-insensitive), `stateReason` (`completed` or `not_planned` for closed issues), `updatedAt` (ISO timestamp), and `labels` (names). Unknown states and duplicate issue numbers are rejected. Each PR can include `number`, `issueNumber`, `url`, `draft`, `author`, `headSha`, `ci.conclusion`, and `reviews` (`author`, `state`, `commitId`, oldest first). A draft PR counts as independently reviewed only when a different author's latest review approves the current head commit and no independent reviewer currently requests changes. PRs without a matching issue appear in Blocked with explicit missing evidence. Missing CI, closure reason, or review evidence is reported as unavailable. Links must use GitHub HTTPS URLs.

The script only reads the named local file and writes Markdown to stdout. It has no GitHub API, token, network, scheduler, or write path. The fixture contains invented `example/test` records only. This prototype is **not a live monitor** and does not replace the existing read-only Hermes 9:00 IST queue job. It does not pick up tasks or change labels.
